# 2026.266.2339 — feat: relocate the check-dsh-pod bed from opencharly/charly (token-aware dsh)

## Summary of changes

Relocate the `check-dsh-pod` R10 check bed (and the `dsh-app` box it deploys) from `opencharly/charly`'s `charly.yml` into this repo, which OWNS the artifact the bed tests — and move the dsh candy to the token-authenticated web UI that `@deepseek-ai/dsh 0.1.7-rc.1` now requires. Supersedes `opencharly/pod-dsh#3` (auto-closed by the 5-BLOCK runaway bound); every finding from its BLOCK verdicts is fixed here, and the previously-red R10 gate is now GREEN.

WHY the relocation: a check bed must live in the repo that owns what it tests. The check-bed runner's dev-tree override (`proc.SelfSuperprojectOverridePair`, `spec/proc/repo_override.go`) points the bed PROJECT's own superproject's `@github` refs at the local tree. In the umbrella every submodule's superproject is `opencharly/opencharly` (which hosts no candies), so a candy owned by another repo was never exercised as in-development code while its bed sat in `charly`. Relocated here, the bed composes the LOCAL candy with no `@github` pin.

WHY the token work: `dsh-web-app >= 0.1.5-rc.x` (here `@deepseek-ai/dsh 0.1.7-rc.1`) mints a random per-process launch token and authenticates every web UI request — a tokenless `GET /` returns **401**. The bump also clears the `0.1.0-rc.6` Cordis-HMR boot crash that failed earlier runs. The candy now captures the token and authenticates every in-box probe. The two probes that read the token live in `opencharly/plugin-dsh` (a separate repo); they were fixed by `opencharly/plugin-dsh#5` (MERGED, squash `819f6f9`), and the bed is green with that plugin compiled in.
