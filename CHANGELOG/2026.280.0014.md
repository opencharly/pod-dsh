# 2026.280.0014 — chore(skill): add `triggers:` to the dsh + dsh-tui skills so the R0 dispatcher routes them

## Summary

Add a `triggers:` phrase to the `dsh` and `dsh-tui` skills so the generated R0
dispatcher routes them. Fixes the two skills' absence from the generated
`DISPATCHER.md` (the class tracked in opencharly/opencharly#382).

### The gap

Both skill entities shipped a `description:` + `content:` but **no `triggers:`**.
`emit_dispatcher.go` emits one `DISPATCHER.md` row per skill with a non-empty
`triggers:` list (`if s.Type == "agent" || len(s.Triggers) == 0 { continue }`), so
neither `dsh` nor `dsh-tui` appeared in the R0 routing table — a dsh task had no row
pointing a session at `/charly-tools:dsh` or `/charly-tools:dsh-tui`.

### The fix

One trigger phrase per skill, naming the candy, the launcher/profile, and the contract
the skill carries:

- `dsh`: the CLI/web candy, `~/.dsh`, the two-layer web auth (launch token + Host/Origin
  fence), `--trusted-host`, exposing dsh web over Tailscale, `charly dsh status` web health.
- `dsh-tui`: the `@deepseek-harness-tui/dsh-tui` plugin, the `dsh-tui`/`dst` launcher, the
  `dsh-tui` profile, `DSH_TUI_NO_LAUNCHPAD`, the terminal:tmux channel, the
  `check-dsh-tui-pod` bed.

The repo's own generator was therefore run over a minimal root carrying the **exact** changed
skill entities from this branch (head `a247979`) plus the real family registry:
