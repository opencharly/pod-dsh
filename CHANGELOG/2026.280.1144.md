# 2026.280.1144 — fix(dsh): install the web profile (bundles + git-hosted plugins) so the layer matches the local dsh setup

## Summary

Make a deployed `dsh-web` pod actually load the community plugins the local
(working) `~/.dsh` loads, by installing the web profile — manifest **and**
`node_modules` — at image-build time and seeding it into the `dsh` volume on
first boot. Supersedes and closes `#22` / `#20`.

Changed paths (one commit, `06f8b0c`):

- `candy/dsh/charly.yml` + `candy/dsh/cordis.patch.yml` (moved from
  `candy/dsh-tui`): ship the ollama-cloud LLM route from the shared `dsh` candy,
  staged to both `~/.dsh` and the durable `~/.local/share/dsh`.
- `candy/dsh-tui/charly.yml`: drop the moved route copy step and the prose that
  referenced it (the route now belongs to the `dsh` candy).
- `candy/dsh-web/web-profile/package.json`: add the three git-hosted community
  plugins, pinned by immutable commit (`opencharly/dsh-github#db37b9b`,
  `dsh-git-worktree#a910ffa`, `dsh-workspace-enhancement#b57db61`), and list all
  **nine** bundles (base + web-app + 4 experimental + 3 community).
- `candy/dsh-web/web-profile/pnpm-workspace.yaml` + `patches/ssh2@1.17.0.patch`:
  `allowBuilds` keyed by bare name (portable across the pnpm pin) + the ssh2
  native V8 fix.
- `candy/dsh-web/charly.yml`: declare `libatomic`/`golang`/`gcc-c++`/`make`/
  `python3`, install `node-gyp`, and install the profile at BUILD time into
  `~/.local/share/dsh/profile-home` (non-volume).
- `candy/dsh-web/dsh-entrypoint`: seed the volume's `profiles/web` from the
  durable copy on first boot (gated on `node_modules`, so a pre-existing volume
  upgrades).
- `charly.yml`: the `check-dsh-pod` `dsh-web-profile-seeded` check now also
  asserts the volume's `ollama-cloud` route (the root `charly.yml` diff).

## Why

Profile bundles resolve from `$DSH_HOME/profiles/web/node_modules`, and the named
`dsh` volume shadows the image's build-time `~/.dsh` — so a deployed pod had none
of the three git-hosted plugins and reported **"Failed to load plugins"**. The
local `~/.dsh` worked only because it had been installed by hand. This makes the
layer reproduce the local config byte-for-byte.
