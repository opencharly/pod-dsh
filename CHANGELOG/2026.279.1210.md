service, and the `~/.dsh` volume is **split by concern** (R3):

- `candy/dsh/charly.yml` — the `dsh:` CLI candy (`@deepseek-ai/dsh` via npm) +
  `package.json` (bumped `0.1.7-rc.1` → `0.2.0-rc.2`).
- `candy/dsh-web/charly.yml` — the `dsh-web:` candy: the loopback web service +
  `dsh-entrypoint` (composes `dsh`).
- `candy/dsh-tui/charly.yml` — the `dsh-tui:` candy: the dsh-TUI plugin + a typed
  `terminal:tmux` channel + `cordis.patch.yml` + `package.json`.

The root `charly.yml` keeps the `skill:` entities, the `dsh-app` (web) and new
`dsh-tui-app` (terminal UI) boxes, and their R10 beds `check-dsh-pod` and new
`check-dsh-tui-pod`.

### Why dsh-TUI is a plugin, not a service

dsh-TUI is a **pure DSH plugin**: it is added to a dsh *profile*
(`dsh plugin --profile dsh-tui add …`) and launched by the shipped `dsh-tui` /
`dst` launcher. It is an interactive TTY UI, so the candy publishes a
`terminal_profile` + `agent_provide: tmux` channel (the `layer-claude-code`
pattern). A terminal channel is on-demand, not a service, so `dsh-tui-app`
composes `check-keepalive` to hold the service-less pod at steady state.

### Deterministic first launch

The TUI's first-run wizard and workspace home own the keyboard on an ordinary
launch. The candy pre-records both (`~/.dsh-tui/onboarding.json` =
`{"completed":true,"version":1}`, `~/.dsh-tui/home.json` = `{"seen":true}`) and
disables the launchpad (`DSH_TUI_NO_LAUNCHPAD=1`), so the TUI lands directly on
the chat composer.

### The two beds

`check-dsh-tui-pod` asserts the image advertises the channel + terminal profile;
drives **one** `terminal:tmux` session (the composer renders, a typed marker
echoes, durable transcript evidence); and proves the **live** provider contract
with a one-shot in-box `dsh headless` turn on the ollama-cloud route — answer
`6158`, absent from the prompt.

**Why the live turn is a one-shot, not a TUI keystroke:** driving the interactive
composer's submit is keyboard-timing sensitive — measured across runs, the TUI
retained the draft in the composer while the model had already answered, so
asserting a live service through the TUI's keystroke path is flaky. The channel
claim is proven interactively (that is what a terminal channel proves); the live
provider claim is proven deterministically, and still runs the REAL route with
the REAL credential — gated per R7a (skips visibly when the key is absent).
