# 2026.280.0641 — docs(dsh): plugin/experimental-feature model + voice model prefetch + dsh-tui incompatibility

## Summary

Document the plugin/experimental-feature model behind the Web Plugins page in the
`dsh` skill, including two runtime traps the model hides. Fixes
opencharly/pod-dsh#17.

### The gap

The skill covered the CLI, the web UI's two-layer auth, and the `dsh-tui` plugin,
but not how Agent Teams / Auto review / Automation tasks / Voice input are enabled
— nor that **composition is not activation**.

### The fix — a new "Plugins and experimental features" section

- Each feature is a **package-bundle** in a profile's `dsh.profile.bundles`
  (`$DSH_HOME/profiles/<name>/package.json`); the Plugins page toggles it by
  writing a `disabled:` override into the profile's `cordis.patch.yml`. Verify with
  `--dump-config` **and** a boot.
- Per-feature table for web vs dsh-tui.
- **Agent Teams**: works in web/headless; needs durable session storage
  (`dsh-session-persistence-jsonl`); durable but **process-local**, one shared
  working directory.
- **Voice input**: activates but needs a one-time **241 MB** SenseVoice model that
  `dsh` does not pre-fetch; the exact verified cache paths + pinned sizes.
- **The `dsh-tui` profile cannot host these bundles** — the dsh-TUI adapter rejects
  `root.effect` (`Error: dsh-tui: root.effect is unavailable from a plugin
  activation`), so adding them makes them fail to activate. Keep it at
  `dsh-base` + `dsh-tui`. There is therefore **no** Agent-Teams coordination
  between the TUI and the web GUI.
