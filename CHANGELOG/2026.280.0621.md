# 2026.280.0621 — docs(dsh): the exposed web URL is https:// + `?token=` — `http://` 400s and a bare host 401s

## Summary

Document the exposed `dsh` web URL's contract in the `dsh` skill's reverse-proxy
section. Fixes opencharly/pod-dsh#15.

### The gap

The section documented the `--trusted-host` Host/Origin fence, but not the URL the
user actually types — so the two ways it fails went unstated. Both measured live
today, on a host exposed with `tailscale serve --bg --https=3080`:

```
$ curl -s -o /dev/null -w '%{http_code}\n' http://a.armadillo-quail.ts.net:3080/
400      # "Client sent an HTTP request to an HTTPS server."
$ curl -sk -o /dev/null -w '%{http_code}\n' https://a.armadillo-quail.ts.net:3080/
401      # bare host — dsh web authenticates every request
$ curl -skL -c jar -o page.html -w '%{http_code}\n' \
    "https://a.armadillo-quail.ts.net:3080/?token=$(cat ~/.dsh/web-token)"
200      # <title>DeepSeek Harness</title>, cookie set (303 -> 200)
```

- `--https=3080` is an **HTTPS-only** listener (`tailscale serve status --json` →
  `TCP.3080.HTTPS = true`, no HTTP entry), so `http://…:3080/` hits the TLS
  server → **400**.
- `dsh web` authenticates every request, so a bare `https://…:3080/` → **401**;
  the token is required.

### The fix

Added to the section: use `https://` (never `http://`), carry `?token=`
(`https://<self>.ts.net:3080/?token=$(cat ~/.dsh/web-token)`), and the
`~/.local/bin/dsh-web-url` helper.
